# OpenReel AI 对话式剪辑架构

## 一句话概括

OpenReel 的 AI 不是直接让模型改 React 页面，而是让模型读取编辑器状态、选择受控的编辑工具，再由工具层调用编辑器已有的项目动作。模型负责理解和规划，编辑器负责校验、执行、刷新时间线和记录撤销历史。

## 主链路

```text
ChatPanel
  -> chat-store
  -> BYOK LLM Client
  -> OpenAI/Anthropic 兼容接口
  -> @openreel/agent runTurn
  -> 工具注册表与工具路由
  -> LiveEditorHost
  -> project-store.executeAction
  -> 时间线和项目状态更新
```

## 每一层做什么

### 1. 对话界面

`apps/web/src/components/editor/chat/ChatPanel.tsx` 负责输入、消息展示、确认、撤销和新建对话。它不直接修改片段，只把用户的话交给 `chat-store`。

### 2. 会话控制器

`apps/web/src/stores/chat-store.ts` 是一轮对话的控制器，主要负责：

- 检查当前是否有项目、API 格式、模型 ID 和密钥。
- 把用户消息和模型消息写入会话历史。
- 根据最近几轮对话选择本轮需要发送给模型的工具。
- 创建可取消的请求，并把工具调用、结果、错误和最终答复同步到界面。
- 读取“自动批准”和“试运行”设置。

### 3. 模型适配层

`apps/web/src/services/agent/llm-transport.ts` 将统一的 Agent 请求转换为两种兼容协议：

- OpenAI 兼容接口：`/chat/completions`
- Anthropic 兼容接口：`/messages`

密钥由用户自己提供，桌面端通过现有的安全存储和请求桥接发送；Web 端使用代理或直接访问用户配置的兼容服务。模型可以替换，业务逻辑不绑定某一家模型。

### 4. 上下文和工具路由

`packages/agent/src/system-prompt.ts` 生成系统提示，注入当前项目的可序列化状态、编辑规则和能力说明。模型首先能看到项目事实，例如轨道、片段、时间和可用枚举值。

`packages/agent/src/tool-router.ts` 不会每轮把全部工具定义都发送给模型，而是：

- 始终保留读取项目和基础动作的工具。
- 根据用户最近几轮文字判断媒体、时间线、导出或动效等方向。
- 保留上一轮已经使用过的工具。
- 将本轮工具数量限制在 120 个以内，减少上下文和服务商限制带来的失败。

工具本身由 `packages/agent/src/registry.ts` 注册。每个工具带有名称、参数结构、所属领域、只读/破坏性/高成本标记和处理函数。

### 5. Agent 工具循环

`packages/agent/src/loop.ts` 的 `runTurn` 执行一轮 Agent：

1. 把当前会话、系统提示和工具定义发送给模型。
2. 如果模型只返回文字，结束本轮。
3. 如果模型返回工具调用，先逐个检查是否需要确认。
4. 交给 `packages/agent/src/executor.ts` 查找工具、解析 `clipId`/`clipIndex`/`atSec` 等片段引用并执行。
5. 把工具结果写回会话，再让模型继续判断是否还需要下一步。
6. 达到完成条件、步数上限或工具调用上限后，返回最终说明。

默认一轮最多 12 步、64 次工具调用。这样“把第一个片段缩短 2 秒”可能先读取片段，再调用修剪工具，最后由模型总结；用户不需要自己填写 UUID 或底层动作格式。

### 6. 编辑器宿主和撤销

`apps/web/src/services/agent/live-host.ts` 实现 `EditingHost`，把 Agent 工具连接到真实编辑器：

- 读取项目时从 `useProjectStore` 获取当前状态。
- 修改时统一调用 `useProjectStore.getState().executeAction(action)`。
- 一轮对话开始时建立 history group。
- 本轮多个动作提交为同一组，用户可以一次撤销整轮 AI 修改。
- 发生错误时结束事务并回滚已应用的动作。

`host-singleton.ts` 复用同一个宿主，避免内置聊天和桌面 MCP 同时改动项目。

## 一次请求的例子

用户输入：

```text
把第一个片段缩短 2 秒，并把后面的内容向前补齐
```

内部过程大致是：

1. `chat-store` 把问题、最近会话和当前项目交给 Agent。
2. 系统提示要求模型先读取片段，再使用具体工具。
3. `tool-router` 选择读取片段、修剪片段和时间线相关工具。
4. 模型调用读取工具，得到真实的片段 ID、位置和时长。
5. 模型调用修剪或移动工具，工具层把引用转换为规范的 `clipId`。
6. `project-store` 更新项目，时间线订阅状态变化后刷新。
7. 工具结果回到模型，模型确认修改完成并返回简短答复。
8. 用户点击撤销时，整轮 history group 一次恢复。

## 安全边界

- 删除、导出和高成本任务会先进入确认卡片。
- 开启“自动批准”后，当前策略允许的工具可以连续执行。
- 开启“试运行”时只生成计划，不应用非只读动作。
- 请求可以取消，过期请求不会覆盖更新后的聊天状态。
- 工具参数由注册表和编辑器动作层校验，模型不能绕过项目状态直接写文件或操作 React 状态。

## 与图片生成的关系

KieAI 图片生成原来是另一条独立链路：素材面板上传图片、创建异步任务、保存任务 ID、后台轮询并把结果写回素材库。它不属于上述对话式剪辑 Agent，也不参与 `runTurn` 的编辑工具循环。

当前 Luna 分支已关闭这条链路的用户入口和应用启动轮询，但暂时保留底层服务、旧项目字段和历史数据兼容代码。当前重点是使用对话 Agent 通过项目动作完成剪辑。
