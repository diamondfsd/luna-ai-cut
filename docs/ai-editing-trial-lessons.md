# AI 导拍与音乐剪辑试验经验

2026-10-03，使用 `/Users/zhouchao/照片同步/lunaultra`，通过软件 AI 助手交接给独立 Codex Agent，执行实际素材分析、计划关联、剪辑、保存重开与导出。用户确认最后一版节奏准确。

## 用户输入与技能的职责

用户只需描述想要的内容、感觉和必要的素材范围，例如：“帮我把这些视频剪个轻快的一日游，多换点画面，跟音乐走。”

用户原话原样进入任务和历史；工作计划、工具参数、选材默认值、素材恢复、卡点校验与已知工具边界由实时技能提供。不能把内部规则改写成用户需求，不能让用户记住工具限制才能得到正常结果。只有缺少会实质影响成片的创作意图或素材范围时才澄清。普通剪辑先交付可编辑预览；导出继续遵守已有用户请求与应用确认流程，技能不增加授权。

## 经验与维护位置

| 经验 | 决策规则 | 当前维护位置 |
| --- | --- | --- |
| 镜头数量不代表视觉丰富 | 先浏览相关候选池，再比较场景、主体、动作和景别；不同文件或不重叠区间也可能仍是同一个视觉内容 | `travel-vlog-story/SKILL.md` |
| 不应靠反复分割少数源凑快切 | 素材充足的短蒙太奇优先新来源，通常同源最多两次且分开；连续动作、采访、素材不足和有意呼应按实际内容判断 | 同上 |
| 音乐要有编曲结构 | 使用完整和弦、低音、旋律、鼓组及辅助层，安排进入、退出、变化和收尾；旋律种子不等于成品配乐 | `music-beat-sync/SKILL.md`、原创模板 |
| 自生成音乐的拍点已知 | 从实际合成 MIDI 读取速度、拍号和鼓事件，不从首个旋律起音重新推断相位；时间信息随导入与项目保存 | 音乐领域服务、`music-beat-sync/SKILL.md` |
| 外部音乐才需要音频识别 | 核对真实检测结果；低置信度不能变成默认速度网格 | 节奏技能与检测引擎 |
| 快切仍要有呼吸 | 音乐先于最终镜头长度，按段落变化密度；主体约1–2秒、局部高潮约0.5秒只是轻快短片的起点，动作完整性和用户风格优先 | 场景与节奏技能 |
| 时间线正确不等于导出同步 | 对照真实输出帧变化与源音频，独立记录编码偏移；依据实测按输出帧率补偿、保留覆盖与首尾，再检查实际文件 | `music-beat-sync/references/export-sync.md` |
| 导入完成不等于重开可用 | 保存来源与曲谱时间；新项目或素材/时间变化时保存重开，等待异步恢复稳定后判断 | 公共技能、导入与持久化模块 |
| 操作限制不属于用户输入 | Agent 读实时技能、工具格式和返回错误；原话不附加诊断步骤、工具参数或模拟授权 | `luna-core`、顶层编辑技能、公共会话指引 |

本记录中的旧技能路径只描述当时使用的实现。当前 PC 侧由 `electron/features/ai-editor/aiEditingToolModule.ts` 提供导拍、素材标注和剪辑工作区技能；公共会话流程由 `electron/features/agent-workflows/agentWorkflowModule.ts` 管理。交接提示词仍只负责服务发现与原始需求，不复制另一份业务手册。

## 本次证据与适用范围

- 上一版21镜头仅来自4个视频，画面仍显重复。目录实际有300视频；最后一版查看同日29源概览与12源细节，使用12源组成20镜头、21秒。没有声称看完全部300视频。
- 音频反推曾取约0.267秒旋律起音为锚点，偏离实际120 BPM曲谱的0/0.5/1秒整拍。改用实际 MIDI 后，草稿19个内部画面边界全部符合曲谱。
- 本机该次 AAC 输出相对 WAV 延后44毫秒。软件内将内部视觉边界补偿1/30秒后重导，独立输出检测的残余差约10.7毫秒，小于30 fps一帧。它不是所有设备、速度、格式或编码器的固定延迟。
- 最后项目保存重开两次，13媒体、20镜头与曲谱时间均恢复正常。目标试验通过，无 renderer 错误；媒体释放的 `ERR_ABORTED` 请求已留证，旧资源找不到错误本轮未复现，不能据此认定其旧根因已解决。
- 视频导入、素材时长、原生节拍模块数组传递、来源持久化、跨项目导入去重和“完成后再导出”识别属于产品实现缺陷，已分别修复。不要把这些修复转成用户需要输入的规避指令。

成片与逐帧/波形验证见 `test-results/ai-editing-trial/lunaultra-diverse-final/`；完整过程总结见 `test-results/ai-editing-trial/session-summary.md`。测试层替代了系统文件选择器返回值，真实导入仍走应用服务；没有验证系统选择器自身。

## 后续验证方法

技能行为检查使用简短口语需求，不把期望工具步骤、计数和故障答案塞进“用户原始要求”。检查 Agent 是否自行选到场景/方法技能、浏览候选、读取生成曲谱、验证保存恢复，并在已有导出授权下检查输出。对没有工具支持的诊断应如实报告能力范围，不通过技能暗示能执行不存在的能力。

维护验证优先技能格式、资源发现、原话保存与相关非界面契约测试。真实剪辑效果属于用户明确要求的交互验收，不因修改技能默认重新运行应用、构建或全量 E2E。
