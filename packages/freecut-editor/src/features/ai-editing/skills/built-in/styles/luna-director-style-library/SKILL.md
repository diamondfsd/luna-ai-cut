# 导演启发式剪辑方法库

这是一个可组合的创作参考库，不是根据用户文案切换宿主工作流的路由器。模型必须结合完整会话判断是否使用某个风格画像；Harness 只负责加载本文件、注册工具和执行模型明确返回的脚本。风格画像改变镜头取舍和默认参数，不能替代素材证据、项目检查、异步等待或最终复核。

## 方法来源与原创边界

本库只提炼公开资料中的通用方法，不复制外部 skill 的原文、示例代码、具体电影场面、台词、角色、分镜序列或可识别调度。参考过的 MIT 许可公开资料包括：

- [volcanicll/remotion-video](https://github.com/volcanicll/remotion-video)：导演画像和镜头语言维度。
- [Melatonin-CZ/minimax-h3-director-prompt-skill](https://github.com/Melatonin-CZ/minimax-h3-director-prompt-skill)：先做风格简报、时间轴镜头表、可观察动作和完成认证。
- [majiayu000/claude-skill-registry](https://github.com/majiayu000/claude-skill-registry)：从画面、灯光和构图中提取可复用观察项的分析流程。
- [thesongzhu/Friday](https://github.com/thesongzhu/Friday)：把场景拆解、转场理由和节奏优化写成剪辑计划。
- [luoluoluo22/jianying-editor-skill](https://github.com/luoluoluo22/jianying-editor-skill)：执行前检查、业务脚本与工具 skill 分离的工程约束。

这些链接是溯源记录，不表示本项目复制或背书外部实现。若资料没有明确许可证，不直接吸收其文本或代码。

## 风格画像的统一格式

选风格时先写一个简短画像，至少包含以下六个维度。导演名字只能作为高层参考标签，最终要落到可观察、可执行的选择：

```yaml
style_profile:
  primary_engine: "一个主导镜头语法"
  secondary_engine: "可选，最多一个，只负责另一段动作"
  composition: "主体位置、空间关系、遮挡和景别"
  camera: "静止或一种主要运镜 + 幅度 + 速度"
  rhythm: "镜头长短对比、切点理由、情绪锚点"
  light_color: "光源、对比度、色彩功能"
  sound: "现场声、声音桥、音乐层级和进入/退出点"
```

一次最多组合两个画像：一个负责建立和停留，一个负责动作或转折。不要在同一个片段里叠加三个以上互相冲突的运镜语法；这会让结果退化为无目的的持续运动。

## 可组合画像

以下是高层方法标签，不是必须照抄的提示词。每个画像都必须让用户素材证据决定是否适用。

### 对称精确

- 构图：中心、轴线、几何形状或明确的画面秩序；需要交代人物关系时保留足够空间。
- 摄影：以静止镜头为主，只有信息变化时才做小幅推近或平移；避免每个镜头都缩放。
- 节奏：少切、长停留，切点落在动作完成或构图秩序被打破的位置。
- 颜色和声音：低到中等对比度或受控的高饱和色；现场声清楚，音乐不抢对白。
- 适用：有明确空间规则、人物被环境安排或需要从整齐走向失序的素材。

### 大尺度氛围

- 构图：用建立镜头交代人与环境的比例，再切到一个具体细节，不用抽象空镜代替内容。
- 摄影：稳定、缓慢、单一方向的推近或跟拍；慢运镜应有足够时长完成，不能用一秒钟的快速缩放冒充慢镜头。
- 节奏：保留呼吸镜头，少量硬切；动作高潮前先让观众看清空间和行动目标。
- 颜色和声音：自然或扩散光，控制饱和度；环境声和低密度音乐共同拉开尺度。
- 适用：自然、建筑、道路、孤独人物和需要从环境读出压力的素材。

### 程序性动势

- 构图：贴近肩部、手部、工具或行动路径，但至少保留一个定位镜头保证空间可读。
- 摄影：动作段落可以使用跟拍和轻微手持，冲击点才提高运动幅度；紧张段落反而可以短暂静止。
- 节奏：快切只用于新信息、动作转折或反应；连续高密度镜头后留一个稳定停顿。
- 颜色和声音：写实光线和清晰的脚步、机械声、呼吸声优先；不要用滤镜遮住动作因果。
- 适用：追逐、操作、倒计时、危险或需要让观众跟上程序的素材。

### 贴身观察

- 构图：近距离跟随人物，允许自然遮挡和不完美的取景，但主体动作必须可辨认。
- 摄影：小到中幅度的手持或跟拍，运动来自人物关系而非装饰性抖动。
- 节奏：按人物动量切成片段化小节；情绪高点可以有一次短慢放，但不能让全片失去生活感。
- 颜色和声音：自然光、真实空间声和画面内音乐优先；音乐来源能看见时优先保留其空间感。
- 适用：人物成长、日常移动、工作现场和需要贴近身体反应的素材。

### 象征碎片

- 构图：用手、物件、反射、门缝、影子或动作后果承载信息；人物不必每次完整露脸。
- 摄影：静止或缓慢单向运动，靠切换到不同证据制造断裂，不靠持续抖动制造不安。
- 节奏：非线性或点状剪辑必须有重复动作、信息缺口或时间断裂作为理由；结尾停在结果或未完成动作。
- 颜色和声音：只给一个物件或局部颜色承担象征功能；声音桥可以先于画面进入，但不得编造未出现的事实。
- 适用：记忆、疏离、心理压力和素材本身已经存在强烈细节的任务。

## 从画像到时间线

### 1. 先读项目和证据

先调用 `luna.project.inspect()` 和 `luna.timeline.inspectContext()`，再读取 `luna.media.list()`、`luna.media.read({ mediaIds })` 及必要的视觉/转录分析。不能因为风格画像写了“门、雨、霓虹、玻璃”就假设素材中存在这些元素。

### 2. 先写镜头表

执行脚本前写出镜头表。每行记录真实 `mediaId`、源区间、目标时长、镜头作用、画面证据、人物/物件动作、声音进入点、声音离开点、切点理由、速度和效果。一个 0.1 秒级事件表只记录状态变化，不要把没有变化的每一帧重复写满。

时间预算的起始参考：

- 静止或呼吸镜头至少 2.5 秒，除非素材明确要求突兀切断。
- 缓慢推近或跟拍通常给 3-6 秒完成；快速动作或冲击点给 0.3-1 秒。
- 开门、拿起、递交等物件状态变化给 1.5-4 秒，并把切点放在动作达到可见终态之后。
- 重要转折放在全片约 40%-75% 的位置，最后 2-3 秒尽量只保留简单停留或反应。

时间表是模型的规划和复核依据，不是 Harness 要解析的第二套协议。模型仍需把它翻译成当前 SDK 的真实调用。

### 3. 映射到 Luna SDK

- 先用 `split`、`trim`、`move`、`remove` 和 `addMedia` 完成粗剪；每组修改后重新读取结构化结果。
- 速度变化使用真实片段 ID 调用 `luna.timeline.setProperties({ itemId, speed })`，或使用项目当前暴露的等价更新能力；慢放会拉长时间线，必须复核相邻片段、原声关联和总时长。
- 需要镜头运动时才使用 `addKeyframe` 或 `setTransform`。当前 SDK 没有生成真实摄影机、烟雾、雨、玻璃或霓虹的能力，不能把提示词中的拍摄要求报告为已执行。
- `gpu-motion-blur` 是可选的方向性曝光拖影，只在动作证据支持且预览需要时使用；慢放和慢门是独立决策。
- 转场以硬切为默认；只有有声音或画面延续理由时才使用 `luna.timeline.addTransition({ type: 'crossfade' })`，写入后检查相邻关系和真实结果。
- 声音桥优先保留对白和现场声，再处理音乐；异步分析或生成任务必须轮询到 `completed` 或明确 `failed`，不能使用未完成资源。

## 完成认证

提交前逐项确认：

- 所有镜头、速度、效果、转场和声音都挂在真实 ID 上，没有重复效果或孤立片段。
- 切点有内容变化或动作理由，空间方向、人物视线和动作终态仍然成立。
- 速度改变后的片段没有源素材越界；总时长、出点、关联原声、静音和淡入淡出已经重新检查。
- 没有把“像某位导演”当成完成证据；未经关键帧、预览或渲染检查的视觉结论必须标记为待确认。
- 输出时分别说明已执行、已读取但未采用、未被当前 SDK 支持和仍需用户确认的部分。

## 反模式

- 不用关键词、正则或固定短语在宿主侧选择导演画像、创建任务状态或决定是否继续调用工具。
- 不把导演姓名扩展成具体电影的复刻要求，不复制台词、角色、剧情和可识别场面。
- 不用连续转场、全片慢放、全片运动模糊、全片压暗或统一滤镜掩盖素材选择和结构问题。
- 不把“情绪”当成不可验证的镜头动作；把它改写成眼神、手势、站位、停顿、声音或可见的物件变化。
