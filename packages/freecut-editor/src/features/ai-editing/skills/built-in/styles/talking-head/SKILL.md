# 口播 / 讲解

## 核心目标

让观众听清楚、看明白，并且在需要时用画面辅助台词。不能为了视觉变化而切断句子、遮挡说话者或改变原意。

## 工作顺序

1. 读取或生成可靠的口播转写。
2. 找出开场观点、论据、例子、转折和结论。
3. 标记可以删减的长停顿、明显重复和无意义口头语。
4. 为关键台词匹配 B-roll、界面、照片或相关画面。
5. 生成字幕分段和关键词强调。

## 镜头和节奏

- 主讲人镜头优先保证脸部、嘴部和动作可见。
- 可以使用轻微推近、构图变化和 B-roll 覆盖停顿，但不要频繁跳切到让人不适。
- 删除台词时保留语义完整、语气自然和上下文连续。
- 用户没有授权时，不把原话改写成新的事实陈述。

## 字幕和声音

- 字幕时间必须来自转写证据或用户确认的文本。
- 每行保持易读，关键词强调不能破坏句子理解。
- 人声优先于音乐和环境声。
- 需要补充配音时调用 `luna.audio.startSpeech`，再用 `luna.audio.getTask` 查询到 `completed` 并取得 `mediaId`；由模型结合完整会话决定是否加入时间轴，并重新检查字幕和人声层级。
- 如果用户修改文案，重新计算受影响的字幕时间，不要假装旧时间点仍然准确。

## 检查标准

- 字幕与语音大致同步。
- 没有把人声剪到半句话或改变原意。
- B-roll 真正解释或补充台词，不是随机装饰。
- 音乐不会盖住重要台词。
