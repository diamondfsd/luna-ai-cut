# 口播短视频剪辑

## 目标

先保证人声、语义和事实完整，再用删减、构图变化、字幕和有依据的补充画面提升信息密度。口播剪辑不是把每个停顿都删除，也不是把每句话都剪成跳切。

## 工作顺序

1. 使用 `luna.media.list` 和 `luna.project.inspect` 确认素材、现有时间轴、画布和轨道。需要依据画面或台词选择镜头时，先使用 `luna.media.read`；没有转写时提交 `luna.media.analyze` 的 `transcript` 任务，轮询 `luna.media.getAnalysisTask` 到结束后再读取结果。
2. 从转写中标记开场观点、问题、论据、例子、转折、结论、口误、重复表达和长停顿。没有可靠时间点时，不要假装知道台词对应的剪切位置。
3. 把剪辑简报组织为：受众结果、开场钩子、主体论证、证据或例子、结论/行动、目标时长、画幅、字幕和声音限制。若删掉整段内容、改变原意或加入新事实会影响结果，先向用户呈现策略再执行。
4. 使用 `edit.run_script` 调用 `luna.timeline.*` 执行粗剪和精剪。脚本中保存每个保留段的素材 ID、源时间范围、台词依据和选择理由，便于下一轮修改。

## 口播粗剪规则

- 优先删除明显的空等、无意义口头语、完整重复句和失误重录；重复句优先保留更清楚、更贴近用户稿件且上下文完整的一句。
- 每个切点落在词或完整语义单元边界，保留约 30-200ms 的自然边界余量；不要切断词、半句话、关键呼吸或句尾音。
- 只压缩确实影响节奏的停顿。保留用于强调、转折、情绪和理解的停顿，避免成片变成机械跳切。
- 用户提供口播稿时，用稿件核对剪后主线；稿件和素材不一致时列出缺失或疑似误剪的段落，不擅自补写台词。
- 大段删除、重排观点或改写事实前，保留可回退的阶段性结果，并让用户确认会改变内容的选择。

## 画面、字幕和声音

- 口播者的脸、嘴部、手势和视线优先。推近、裁切或 B-roll 只用于强调信息、遮盖安全切点或改善构图，不要为了变化遮挡主体。
- B-roll、截图和图卡必须有素材证据或明确标为示意；不能根据文件名、用户形容词或模型猜测制造事实画面。
- 字幕来自转写或用户确认的文字，按短语和语义分段，保证足够阅读时间、对比度和画布安全区。关键词强调服务理解，不替代完整句意。
- 人声和关键现场声优先于音乐。没有节拍时间点时，按句子、动作、段落和声音桥接组织节奏，不声称已经自动卡点。
- 需要文字片段时使用 `luna.timeline.addText` 或 `luna.timeline.addTextBatch`；需要画面变化时使用真实的 `luna.timeline.setTransform` 或 `luna.timeline.addKeyframe` 能力。

## 检查

完成一组剪辑后重新调用 `luna.project.inspect` 或 `luna.timeline.inspectContext`，检查没有半句、黑帧、过短镜头、重叠字幕、明显音频爆点和错误轨道关系。工具结果只证明写入成功，不等于渲染预览或最终文件已经通过；缺少真实渲染证据时必须如实说明未验证部分。
