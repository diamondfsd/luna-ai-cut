# 通用剪辑技巧手册

## 先按信息和动作剪

每个切点都要回答一个可观察的问题：信息是否改变、动作是否进入下一阶段、声音是否带出下一场，或观众是否需要新的画面证据。先建立镜头表，再安排时间轴，不用装饰性切换掩盖内容缺口。

- 开头优先展示真实的主体、结果、问题或冲突；不能用未经证实的镜头制造悬念。
- 主体按信息单元组织，镜头长短随台词、动作和理解难度变化，不强行每隔固定秒数切一次。
- 转折前可以减少切点、让声音先行或保留反应；重点处增加信息、景别或声音变化；结尾给完整动作、环境声或结论留出空间。
- 同一段画面长时间没有新信息时，优先加入真实的构图变化、局部高亮、文字节点或补充画面，而不是无意义闪动。

## 镜头连接

- **硬切**：观点、动作或空间明确变化时使用，适合信息清晰和节奏利落的内容。
- **动作切**：在动作进行中切到动作的下一阶段或相近方向，先检查实际动作连续性。
- **匹配切**：只在形状、方向、颜色、动作或声音有真实对应关系时使用。
- **J Cut**：下一镜头的声音先进入，用于预告地点、人物或下一段话题。
- **L Cut**：上一镜头的声音延续到新画面，用于反应、回忆或空间延续。
- **淡化和溶解**：用于时间经过、情绪转折或段落结束，不要把每个镜头都套上溶解。

## 声音和节奏

人声、对白和关键现场声优先于音乐，环境声用于保持空间真实感，音乐负责情绪和段落推动，音效只在动作或重点出现时使用。没有可靠节拍分析时，不把段落切点描述为卡点；可以按句尾、动作落点、情绪转折和声音桥接组织节奏。

口播或对白中，语义完整和听感自然优先于鼓点。使用 `luna.timeline.setAudio` 调整音量、淡入和淡出；需要生成声音时先用 `luna.audio.startSpeech` 或 `luna.audio.startMusic`，再轮询 `luna.audio.getTask`，只有任务完成并返回 `mediaId` 后才决定是否加入时间轴。

## 字幕和画面变化

字幕来自转写证据或用户确认的文本，按语义分段并避开脸部、手势和关键画面。文字层一次只强调一个主要观点；多个步骤或数据卡应随口播节点分批出现，不要在段落开始时一次性打满画面。颜色、裁切、推近和变速都要服务理解或情绪，不能把模型猜测写成字幕事实。

## 执行方式

通过 `edit.run_script` 在一个脚本中完成读取、判断、批量写入和复核。使用真实的 `mediaId`、片段 ID 和转场预设；添加转场前先调用 `luna.timeline.listTransitions`，批量操作优先使用 `luna.timeline.addMediaBatch`、`luna.timeline.addTextBatch` 或 `luna.timeline.addTransitionBatch`。每次写入都读取结构化结果，完成一组修改后再次检查时间轴。
