# Luna 画面精修与交付复核

## 适用场景

当用户要求加转场、推拉镜头、关键帧、调整画面统一或检查成片是否可以交付时使用。它不能替代粗剪、字幕和声音结构，也不能把当前 SDK 没有提供的渲染或色彩工具假装存在。

## 精修顺序

1. 先读取时间线，确认结构、轨道、片段相邻关系已经稳定，再开始精修。
2. 先处理曝光、白平衡和相邻镜头统一；HDR、HLG 或 LOG 素材先确认色彩转换。当前 SDK 没有明确的调色能力时，记录待处理项，不生成虚构的 `luna.*` 调色调用。
3. 转场只表达镜头关系。信息清楚和动作连续时优先硬切；需要延续或柔和连接时使用当前支持的 `type: 'crossfade'`。
4. 关键帧、缩放、平移和速度变化必须服务于引导视线、保持主体、建立空间或强调信息，不为装饰给每个片段添加运动。

## 安全执行

- 添加转场前调用 `luna.timeline.inspectContext()`，确认两个片段在同一视频轨道、时间轴上相邻，且前后片段有足够的源素材余量。
- 使用 `addTransition({ fromClipId, toClipId, type: 'crossfade', durationSeconds })`；失败后重新读取错误和时间线，不假设转场已经存在。
- 使用 `addKeyframe()` 时只传当前 SDK 支持的属性和值，确认开始、重点和结束位置不会让主体或字幕出框。
- `setTransform()`、`setProperties()` 等写入后立即读取受影响片段；不要把数组位置或旧 ID 当作当前事实。

## 交付前检查

- 重新检查轨道层级、片段范围、相邻关系、转场、关键帧、字幕轨道和音频轨道。
- 检查是否存在空白段、意外重叠、黑帧风险、未处理错误或异步任务遗留；发现问题先报告，不以脚本成功结束代替复核。
- 当前 SDK 没有独立渲染、逐帧截图、响度测量或导出结果验证能力时，明确列出“结构已复核、视觉/声音/导出待实际预览”的边界。
