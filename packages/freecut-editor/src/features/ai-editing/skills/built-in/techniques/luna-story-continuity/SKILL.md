# Luna 故事与连续性

## 适用场景

当素材顺序混乱、对话关系不清、人物或运动方向跳变、B-roll 缺少目的，或用户要求更像电影和纪录片的连贯剪辑时使用。它提供镜头选择和排序判断，不凭空生成不存在的画面证据。

## 镜头选择

- 先读取项目和素材证据；需要画面判断时调用 `luna.media.read()`，必要时提交 `visual` 分析并等待完成。
- 为段落识别建立空间的镜头、承载动作的镜头、人物反应镜头和表达重点的细节镜头。只有在素材证据支持时才使用这些角色。
- 同类镜头优先保留信息量、动作完整度、情绪和稳定性更高的版本，避免连续使用几乎相同的构图。
- B-roll 必须补充地点、动作、物件、过程或情绪信息；不能用与台词无关的漂亮镜头遮盖内容缺口。

## 连续性检查

- 对话检查人物左右位置、视线方向、反打关系和动作衔接；运动场景检查运动方向和切点。
- 保持同一段落的屏幕方向和空间关系。若必须越轴，使用建立空间的镜头、明确的运动或其他有证据的过渡让观众理解变化。
- 同一动作或观点的切换优先落在动作遮挡、动作延续或反应成立的位置；发现跳切时先调整覆盖镜头或片段范围，不用随机转场掩盖。
- 连续性规则是辅助判断，不是固定删除规则。低置信度时保留候选并说明需要预览确认的部分。

## 时间轴执行

- 用 `luna.timeline.addMedia()` 或 `addMediaBatch()` 加入已经确认的素材，用 `move()`、`trim()` 调整顺序和范围。
- 添加画面叠加或 B-roll 前先规划视频轨道和层级；使用真实返回 ID，不依赖轨道数组顺序。
- 每完成一个段落重新读取 `luna.timeline.inspectContext()`，确认片段相邻关系、轨道层级和关联音频没有被意外改变。

## 完成复核

- 观众能够判断人物、地点、动作和段落关系；镜头顺序有叙事理由。
- 使用的素材 ID 都来自当前项目证据，未把未分析或不存在的镜头写入时间线。
- 视觉连续性无法通过当前 SDK 直接验证时，明确标记为待预览确认，不报告为已完全修复。
