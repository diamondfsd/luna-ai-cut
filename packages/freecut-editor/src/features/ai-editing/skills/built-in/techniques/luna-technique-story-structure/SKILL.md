# 叙事与镜头结构

## 目标

把素材组织成观众能看懂的事件、人物和情绪关系。先建立内容结构，再决定镜头长度、声音和转场，不用漂亮镜头掩盖故事缺口。

## 工作流

1. 先调用 `media.list` 和 `project.inspect`，需要判断画面或台词时读取 `media.read`；证据不足再分析。
2. 把素材分成建立环境、人物/主体、动作、细节、反应、结果和收尾，不按文件名猜内容。
3. 先写内部镜头表：镜头角色、来源范围、预计时长、前后关系、声音主导和字幕需求。
4. 用 `timeline.add_media_batch` 批量加入已经确定的镜头；依赖新片段 ID 的操作等待结果后再做。
5. 每组写入后调用 `project.inspect` 或 `timeline.inspect_context` 复核时间范围和轨道。

## 结构模板

- **时间顺序**：建立地点/人物 -> 事件展开 -> 关键结果 -> 收尾。适合家庭记录、旅行和活动。
- **问题到结果**：先展示问题或目标 -> 证据与行动 -> 转折 -> 解决或结论。适合教程、产品和知识视频。
- **主题蒙太奇**：按人物、动作、色彩、地点或物件呼应排列，允许跳出拍摄顺序，但要保留可理解的线索。
- **先结果后过程**：用真实的高信息镜头开场，再补充过程和背景；不能用未经证实的画面制造悬念。

## 连贯性检查

- 保留动作的起点和结果；动作中途切换时，用 `luna-technique-cutting-rhythm` 判断是否能以动作匹配。
- 保持基本方向、视线和时间关系；证据不足时宁可使用建立镜头或明确的硬切，不要编造空间关系。
- 高潮前增加信息或声音密度，高潮后留出反应、环境声或结论，不把所有镜头剪成同一种长度。
- 不能用模型对人物情绪的猜测写成事实字幕。

## 当前工具边界

结构规划和时间轴编辑可以直接执行。分镜图、复杂跟踪或自动故事理解没有专用工具时，只输出可执行方案和证据缺口。
