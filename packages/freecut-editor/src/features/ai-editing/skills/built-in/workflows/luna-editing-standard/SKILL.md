# Luna 标准剪辑工作流

这个技能把真人剪辑中的判断方法转换为可以在 FreeCut 中执行和复核的步骤。它适用于没有指定特殊风格的普通剪辑任务，也可以作为口播、旅行记录、教程和短视频等场景技能的基础。

## 核心顺序

始终按下面的优先级推进：

1. 先确认任务目标、素材范围、画幅、时长、受众、节奏、声音、字幕和交付限制。只询问会实质改变剪辑结果的缺失信息；其他信息使用明确记录的默认值。
2. 先建立故事、空间和动作的连续性，再处理镜头长度和节奏。
3. 先完成粗剪和结构调整，再加入字幕、音乐、转场、关键帧和风格化调色。
4. 每次写入后读取结构化结果；完成一组相关操作后重新检查时间线，再决定下一组操作。

## 证据优先

在提出具体剪辑决定前，先通过 SDK 读取当前项目的真实状态：

- 第一次编辑调用 `luna.project.inspect()` 和 `luna.timeline.inspectContext()`。
- 需要选择素材时，先调用 `luna.media.list()`，再用 `luna.media.read({ mediaIds })` 读取已有证据。
- 需要台词或画面分析时，提交 `luna.media.analyze({ mediaIds, kind })`，轮询 `luna.media.getAnalysisTask({ taskId })` 到 `completed` 或 `failed`，完成后重新读取素材证据。
- 只使用 SDK 返回的真实项目、素材、轨道和片段 ID。文件名、旧摘要和模型推断不能替代当前项目证据。
- 分析或生成任务没有完成并返回有效结果时，不把它加入时间线，也不向用户报告为已完成。

如果当前没有足够证据支持一个剪辑决定，说明未知内容并先补充证据；不要为了让流程继续而猜测镜头内容、人物关系、时间戳或轨道层级。

## 结构和镜头判断

### 先讲清楚

- 用能建立主体、地点或动作的镜头开始段落；保留对观众理解主题有帮助的空间交代。
- 同类镜头优先保留信息量更高、动作更完整、情绪更明确或画面更稳定的版本，不按“清晰”一个条件批量保留。
- 通过远景、中景、近景、细节和反应镜头形成有效对比。连续性不足时，优先调整镜头顺序或补充覆盖镜头，不用效果掩盖结构问题。
- 对话和动作场景检查人物位置、视线方向、运动方向、动作衔接和时间关系。发现越轴、跳切或关系不清时，给出有证据的候选调整。
- 结尾应有动作、信息或情绪上的收束。素材自然结束不等于叙事已经结束。

### 节奏服务内容

- 镜头长度由对白密度、动作速度、信息量和情绪变化共同决定，不使用固定秒数作为永久规则。
- 快速段落之间保留必要的定位和呼吸镜头；平静段落需要变化时，优先寻找动作、景别或信息上的变化。
- 开头建立兴趣，中段推进信息或冲突，结尾完成收束。短内容也要保持可理解的起承转合。
- 删除静音、口头停顿、重复观点或填充词前，阅读完整台词上下文，区分可删候选和有叙事作用的停顿。

## 声音优先级

- 先保证对白、呼吸、反应和空间连续，再选择音乐和音效。
- 使用 J-cut 或 L-cut 必须有明确目的，例如预告下一段声音、延续上一段情绪或桥接空间；不要为了形式给每个切点添加声音效果。
- 切分音频后检查切点连续性，必要时使用淡入、淡出或交叉淡化避免爆音和点击声。
- 音乐、环境声和音效应放在独立音频轨道，并为对白保留清晰的听感层级。
- 生成 TTS、音乐或音效时遵守共享异步任务契约；任务提交成功不代表媒体可以使用。

## 画面、字幕和效果

- 字幕、标题和其他画面叠加使用独立视频轨道，并确认其层级高于被覆盖的画面轨道。
- 字幕分组应跟随语义、停顿和画面节奏；检查字幕组不重叠、不过长、不出安全区域，也不遮挡关键主体。
- 先做曝光、白平衡和相邻镜头统一，再做创意风格。HDR、HLG 或 LOG 素材先确认正确的色彩转换，不重复套用已经存在的处理。
- 转场表达镜头关系。连续性和信息清楚时优先硬切；需要延续或柔和连接时才使用当前 SDK 支持的 `crossfade`，并先检查两个片段的源素材余量。
- 关键帧、缩放、平移和速度变化都必须有视觉目的，例如引导视线、保持主体或强调信息；预览开始、重点位置和结束位置，确认主体和字幕没有出框。
- 如果当前 SDK 没有提供某项视觉分析或预览能力，不虚构已经完成的视觉验证，并把未验证项返回给模型和用户。

## 通过 SDK 执行

- 唯一编辑入口是 `edit.run_script`，脚本导出 `default async function main(luna)`；不要直接修改项目文件、内部 Store 或 Electron 状态。
- 脚本先读取上下文，再使用 `result.data` 中的结构化结果。时间参数按共享契约使用秒，不能把素材源时间和时间轴时间混用。
- 先规划轨道，再批量执行同类操作。创建轨道后使用返回的真实 ID；移动轨道前读取当前轨道层级，不依赖数组顺序。
- 写入失败后重新读取项目和时间线，基于错误结果调整方案；不要假设失败的操作已经生效。
- 删除、解除关联、静音、移动和重排都要考虑关联片段、轨道层级和后续时间映射。保留来源和未采用镜头的决定，不把不确定候选直接永久删除。

## 完成条件

只有在以下证据齐全时，才能向用户报告对应部分已完成：

- 任务目标与实际修改范围一致。
- 所有使用的素材、轨道、片段和生成媒体都来自当前项目的结构化结果。
- 异步任务已经明确完成，失败任务没有被继续使用。
- 时间线重新读取后，轨道层级、片段范围、音画关系、字幕位置和关键操作结果符合方案。
- 没有可见的未处理错误；缺少预览、渲染或导出验证时，明确列出未验证项。

工具返回成功、脚本执行结束或模型已经生成方案，都不能单独作为剪辑完成的依据。用户消息、模型回复和工具名称也不能被宿主代码用关键词推断成意图、工作流状态或完成状态。

## 技能组合

`luna-editing-master` 负责项目读取、任务分解、SDK 协议和最终复核；本技能负责通用真人剪辑判断。用户指定的风格、平台和交付要求优先于这里的默认取舍。更具体的场景技能只补充局部偏好，不得绕过证据读取、异步等待和复核要求。
