# 短视频生产流程

## 1. 素材和项目预检

先调用 `luna.media.list` 和 `luna.project.inspect`，确认素材类型、时长、尺寸、帧率、音频状态、当前画布、轨道和已有片段。不要覆盖原始素材，也不要依据文件名推断内容。只有用户明确要求竖屏或发布场景明确为竖屏时，才用 `luna.project.setCanvas` 设置 `9:16`；其他情况保留现有画布或先询问。

## 2. 转写和剪辑简报

口播、访谈和讲解内容先读取现有字幕；没有结果时提交 `luna.media.analyze` 的 `transcript` 任务，轮询 `luna.media.getAnalysisTask` 到 `completed` 或 `failed`，再用 `luna.media.read` 读取。把内容整理成开场、问题、展开、证据、转折、结论和行动，并记录目标时长、画幅、字幕、音乐和必须保留的内容。

如果用户给了脚本，使用原文做对稿，不把脚本当作视频中已经说过的内容。对于大段删减、重排叙事、添加 B-roll、配音或音乐等会改变作品方向的选择，先给出简短策略并等待用户明确选择；用户已经明确授权时可直接执行。

## 3. 粗剪

依据词或完整语义单元选择保留段，删掉明确的空等、口误和重复表达，保留必要呼吸、转折和完整句尾。切点保留约 30-200ms 的自然余量，避免切词、爆音、黑帧和动作断裂。多个同类片段使用 `luna.timeline.addMediaBatch`，依赖新片段 ID 的操作等待上一结果。

## 4. 画面、字幕和声音

- 画面变化优先使用真实 B-roll、构图变化、局部推近、关键词文字或证据卡片；所有补充内容都要有来源或标记为示意。
- 字幕按口播语义分段，保证可读时长、安全区和与声音的大致同步。字幕应在其他图层确定后加入或调整，避免被卡片、人物和关键画面遮挡。
- 人声和现场声优先于音乐。没有节拍分析结果时按句子、动作和段落组织，不声称自动卡点。
- 当前工具不提供完整的自动平台审核、专业降噪、节拍检测或真实渲染审片能力时，只给出方案或报告证据缺口，不把计划说成已经完成。

## 5. 预览和质量复核

每完成一组写入，调用 `luna.project.inspect` 或 `luna.timeline.inspectContext` 复核轨道、时间范围、源素材和转场关系。重点检查开头是否直接进入主题、台词是否被截断、字幕是否来得及阅读、人物是否被遮挡、音乐是否盖住人声、画面是否出现空白或过密信息。

只有拿到真实渲染或预览结果后，才能报告画面级 QA 已完成。仅有工具返回的项目 JSON 或时间轴摘要时，应明确说已完成结构检查，渲染、同步和最终文件仍待验证。

## 6. 交付和后续修改

向用户报告主风格、剪辑结构、实际写入的修改和未验证项。保留用户可以继续修改的时间轴，不把一次性风格规则固化成不可逆模板。后续反馈只调整对应片段、字幕、声音或画布，除非用户要求重新设计整体结构。
