# Luna 口播剪辑

这是一套以说话内容为主线的剪辑工作流，适用于单人口播、教程、访谈回答、知识分享和带讲解的屏幕录制。它不是“检测到静音就删除”的机械规则，也不是宿主根据用户文案切换状态的路由器。模型应结合完整会话、素材证据和当前项目判断是否使用本技能；Harness 只负责提供能力、执行模型明确返回的脚本并回传结构化结果。

本技能应与 `luna-editing-master`、`luna-editing-standard`、`luna-rough-cut`、`luna-audio-editing` 和 `luna-caption-layout` 组合使用。它补充口播判断，不替代通用的项目读取、异步等待、时间线契约和最终复核。

## 口播剪辑的目标

口播剪辑通常同时追求四件事：

1. 让观众尽快听到主题、观点或问题，不把开场的试音、寒暄和找状态留在成片里。
2. 让表达更紧凑，但仍像一个人在自然说话，而不是把每个呼吸都抹掉。
3. 保留讲者的个性、强调、反应、笑声和必要的停顿，不把“干净”剪成没有人味。
4. 让画面切点、原声、字幕和最终时间轴使用同一套时间依据。

## 公开方法的提炼边界

本技能只吸收公开资料中可泛化的编辑方法，不复制外部 skill 的原文、脚本、具体项目结构或视觉模板。参考过且许可证明确的资料包括：

- [francoeur003/chatcut-video-editing-skill](https://github.com/francoeur003/chatcut-video-editing-skill)，MIT：先完成 A-roll，再做声音平滑、字幕、效果和验证；压缩停顿不能等于删除全部呼吸。
- [Georgellx/edit-talking-head-video](https://github.com/Georgellx/edit-talking-head-video)，MIT：使用词级转录、保留语义完整性、在切点使用有限边缘余量，并从成片时间重算字幕。
- [kingbootoshi/video-alchemy](https://github.com/kingbootoshi/video-alchemy)，MIT：保留完整表达单元、检查标点 token 和切点是否跨越词语、用 keep-list 表达重剪结构。
- [OpenClip-App/agent-skills](https://github.com/OpenClip-App/agent-skills)，MIT：转录任务异步提交、轮询完成后再读取带时间的结果。

这些链接用于方法溯源，不表示 Luna 复制或依赖外部工具。没有明确许可证的候选资料不直接吸收其文本或代码。

## 第一原则：先分析完整音频字幕

### 第一次读取

编辑前必须按以下顺序读取真实项目：

1. 调用 `luna.project.inspect()` 和 `luna.timeline.inspectContext()`，确认当前项目、轨道、视频片段、关联音频和时间轴范围。
2. 调用 `luna.media.list()` 找到当前项目中的视频和独立音频；优先确认带人声的 A-roll 和它的 `linkedGroupId` 关联关系。
3. 对候选口播素材调用 `luna.media.read({ mediaIds })`。完整读取转录，不只读取开头或模型摘要。
4. 如果返回的转录状态不是 `ready`，调用 `luna.media.analyze({ mediaIds, kind: 'transcript' })`，再轮询 `luna.media.getAnalysisTask({ taskId })`，直到 `status === 'completed'` 或 `status === 'failed'`；之后重新调用 `media.read()`。
5. 分析任务失败、素材不存在、转录为空或结果明显不完整时，停止破坏性剪辑并向模型返回明确的失败原因。

一次分析最多提交当前 SDK 接受的媒体数量；超过上限时分批处理，所有批次完成后再统一规划。已存在且更新时间仍匹配的转录可以复用，不要无理由重复分析。

`media.read()` 返回的转录片段时间是源素材时间。若结果包含 `words`，优先使用词级时间；若只有 `segments`，只能把句段边界当作较粗的候选，不能假装已经拿到词级精度。

### 口播分析表

模型在写时间线脚本前，先基于完整转录形成内部镜头/内容表。每个表达单元至少记录：

| 字段 | 内容 |
| --- | --- |
| source | 真实 `mediaId` 和源片段/视频 ID |
| range | 源素材起止时间；有词级时间时记录首词和末词 |
| quote | 讲者实际说出的原话 |
| beat | 开场钩子、问题、观点、步骤、例子、转折、总结或 CTA |
| decision | 保留、删除、压缩、待确认 |
| reason | 叙事或听感理由，不写“模型觉得不好” |
| audio | 呼吸、笑声、环境声、原声连续性和切点风险 |
| caption | 术语、数字、专名和字幕分组注意事项 |

不要只看孤立的一个字幕片段。每个删除候选都要连同前后至少一个完整表达单元阅读，检查主语、指代、因果、否定词和结论是否仍然成立。

## 保留、删除和待确认

### 默认保留

- 能提出主题、问题、承诺或结果的开场内容。
- 解释因果、步骤、定义、例子、对比和结论的完整句子。
- 讲者的强调、笑声、惊讶、犹豫、反应和能建立可信度的自然表达。
- 连接前后逻辑所需的“所以”“但是”“这件事”“这个阶段”等指代词。
- 观点转折前的必要停顿，以及 punchline、结论或 CTA 之后的反应和落点。
- 让观众看清屏幕操作、道具、手势或表情的必要画面，即使它不是最高信息密度的语句。

### 常见删除候选

删除前必须检查上下文和替代表达：

- 开始录制后的试音、找状态、无内容寒暄和重复开场。
- false start、口吃堆叠、说到一半放弃后重新完整开始的旧句子。
- 只包含填充词的独立片段，例如“嗯”“呃”“那个”“就是”，但要区分它们在句子中的实义用法。
- 没有新信息的同义重复、进度播报、空洞过渡和跑题段落。
- 自我纠正：先说错后立即完整纠正的旧表述，不能只删除“不是/不对”，要一起判断前面的错误句和后面的正确句。
- 讲者已经给出完整答案后又重复一遍、且没有新增例子或强调目的的段落。
- 不承担情绪、节奏、空间或逻辑作用的长停顿。

### 必须谨慎

- 不要自动删除所有静音、呼吸和句间停顿。短呼吸通常是自然听感的一部分。
- 不要只按 ASR 标点切割；ASR 标点可能和说话停顿不一致，先看时间和语义。
- 不要从不同句子拼出讲者没有说过的观点，也不要为了满足时长删除必要的限定词、否定词或例外条件。
- 不确定是口误、术语还是讲者的个人表达时，列为待确认，并保留原片段。
- 讲者正在展示操作、等待反馈、看向屏幕或做手势时，视觉上的停顿可能有信息，不能按音频空白单独删除。

## 停顿和切点参数

以下是模型的起始判断，不是宿主硬编码阈值；用户节奏、内容密度和素材证据优先：

```yaml
speech_editing:
  default_style: natural_tight
  phrase_pause_keep_seconds: [0.15, 0.35]
  topic_change_pause_keep_seconds: [0.35, 0.6]
  long_pause_review_threshold_seconds: 0.8
  obvious_dead_air_review_threshold_seconds: 1.5
  edge_padding_seconds: [0.03, 0.2]
  caption_pass: after_structure_lock
```

- “更紧凑”的普通口播：先把无功能长停顿压到约 `0.15-0.35` 秒，保留句间呼吸；不要把整条视频处理成零停顿。
- 主题切换、重点前后和 CTA 前后：优先保留约 `0.35-0.6` 秒的空气，除非用户明确要求高密度快切。
- 超过 `0.8` 秒的停顿进入候选列表，超过 `1.5` 秒才可作为强删除候选；两者都要结合画面和语义判断。
- 切点通常落在首个保留词之前、末个保留词之后，保留约 `30-200ms` 的边缘余量。切点落在连续说话内部时，必须有词级时间或清晰的预览证据。
- 如果只有句段时间而没有词级时间，优先在句段之间切，或把该处标记为需要预览，不要报告为精确口播切点。
- 切点不能跨越一个未完成的词、否定词、数字、专名或句末标点；保留句末自然落音，再处理尾部空间。

## 执行顺序

### 1. 先锁定内容结构

根据分析表确定成片顺序：

```text
开场钩子/问题
  -> 主题承诺
  -> 核心观点或步骤
  -> 例子/证据/演示
  -> 结论或 CTA
```

教程可以使用“问题 -> 步骤 -> 注意事项 -> 总结”，访谈可以保留“问题 -> 回答 -> 追问 -> 回答”。这只是结构参考，不强行套用。不要为了追求短而删除完整的论证链。

若有多条 take，先在转录中按同一个表达单元比较完整度、流畅度、事实准确性和画面状态，再选最好的整段。没有可靠的同步依据时，不要把不同 take 的音节拼成一句话。

### 2. 执行 A-roll 粗剪

- 先保存镜头顺序和关联关系，再用 `luna.timeline.split()`、`luna.timeline.trim()`、`luna.timeline.move()` 和 `luna.timeline.remove()` 执行内容取舍。
- 所有时间参数是当前时间轴绝对秒数；源素材转录时间只有在映射到当前片段后才能用于切点。
- 使用真实的视频片段 ID。每次 split 后，旧片段 ID 可能失效，必须读取返回的 `leftId`、`rightId` 或重新 `inspectContext()`。
- 带伴侣音频的视频片段优先保持关联一起剪。若确实要单独删除伴侣音频，使用 `luna.timeline.removeAudio({ itemIds })`；它会自动解除关联并保留视频。不要删除视频来代替删除原声。
- 同一组剪辑尽量批量完成，但每组写入后都要重新读取时间线，确认没有黑隙、重叠、源素材越界、意外静音或音画脱离。
- 默认硬切。口播 A-roll 的连续跳剪不靠装饰性转场掩盖；有明确的空间或 B-roll 衔接理由时才使用 `crossfade`。

### 3. 处理声音接缝

- 结构稳定后，再调用 `luna.timeline.setAudio()` 设置必要的 `fadeIn`/`fadeOut`，处理切点爆音和突兀断裂。
- `volume: 0` 是正常音量，不是静音；静音必须明确使用 `muted: true` 或 `luna.timeline.mute()`，并检查返回值。
- 原声优先于音乐。没有明确需求时不自动加音乐；已有音乐不能盖住口播重点。
- J-cut/L-cut 只在下一段内容需要提前预告或上一段声音需要延续时使用，不给每一个跳剪都加声音桥。
- 不凭结构化时间线声称“听感已经完美”；没有实际播放、预览或响度测量时，报告为音频结构已复核，听感待预览。

### 4. 最后生成字幕

口播字幕必须建立在剪辑后的时间轴上：

- 粗剪、移动和速度变化完成后，重新从保留的转录片段计算成片时间；不能把源素材时间直接当成输出字幕时间。
- 以完整语义单元分组，优先在句末、自然停顿、主谓宾/修饰关系和枚举边界断句，不按固定字数硬切。
- 术语、数字、专名和否定关系优先保持准确；ASR 不确定时保留原文并标记待校对，不凭空修正。
- 字幕使用独立视频轨道或当前项目支持的字幕数据结构，确认层级、安全区、字幕持续时间和相邻 cue 不重叠。
- 字幕应在结构稳定后才加入；之后任何片段删除、移动、trim 或 speed 变化都必须重新映射字幕时间。
- 字幕能否读清、是否遮住脸、手势、屏幕文字或产品，需要预览帧确认，不能只根据数据结构报告完成。

## 口播常见画面处理

- 没有 B-roll 时，优先依靠内容切点、适度景别变化或少量 `setTransform()` 保持节奏；不要每句话都 punch-in。
- zoom、裁切和关键帧只在重点、章节变化或需要遮盖合理跳切时使用；脸、手、屏幕内容和字幕不能出安全区。
- 有画面证据且用户允许时，B-roll 可以覆盖口播画面，但口播音频仍应保持连续，并把 B-roll 的输出时间映射到剪辑后的时间轴。
- 不凭空生成讲者没有拍摄的反应、道具、屏幕、空间或动作；视觉风格不能替代素材证据。

## 完成复核

提交剪辑脚本前后分别复核：

### 内容和时间线

- 开头尽快进入主题，结尾有完整结论、CTA 或自然落点。
- 删除后的台词仍保留主语、指代、因果、否定和论证顺序。
- 没有切在词语内部、句中关键连接词、数字或专名中间；每个切点都有语义或听感理由。
- 视频、伴侣音频、独立音轨和字幕的范围、关联、静音状态与轨道层级一致。
- 没有空白段、重叠、黑帧风险、源素材越界或因 speed 变化造成的总时长错误。

### 声音和字幕

- 连续口播的切口没有明显爆音或断裂；必要的淡入淡出已经写入真实音频片段。
- 字幕基于成片时间重算，cue 不重叠，文本对应正在说的语义，术语和数字经过上下文检查。
- 音乐和音效没有盖住人声；未测响度时不要声称符合平台响度标准。

### 预览边界

- 有预览能力时，至少检查开头、每个跳剪前后、最密集字幕处、重要观点/CTA 和结尾。
- 最好一次完整听音频、一次关闭声音看画面；发现音画不同步、口型跳变、字幕错位或切得过紧，先修复再报告。
- 未做实际预览、渲染或导出验证的部分，必须明确写为“结构已复核，视觉/听感/导出待确认”。

## 不允许的捷径

- 不把静音检测结果直接变成删除操作。
- 不只读转录摘要或局部字幕就决定删除一整段。
- 不只删除“不是/不对”而保留前面的错误表述。
- 不用关键词、正则或固定短语在宿主侧判断用户是否要剪口播、决定继续调用工具或宣告完成。
- 不修改项目文件、内部 Store 或导出文件来绕过 `edit.run_script` 和 SDK 复核。
- 不在 A-roll 结构尚未稳定时先做字幕、音乐、复杂效果或全片变速。
