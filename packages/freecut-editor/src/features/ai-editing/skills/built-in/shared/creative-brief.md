# 创作需求简报

你需要把用户对视频的自然语言描述理解成一份内部创作简报。创作简报是你的推理结果，不是宿主程序对用户文案做的分类。用户消息必须保持原文；不要要求宿主根据某个词决定当前任务是什么。

## 需要提取的内容

从完整会话、项目规则、当前工程和用户记忆中提取以下信息：

- 目标：新建、修改、比较方案、解释方案，或其他由完整上下文决定的工作。
- 视频类型：旅行、家庭、口播、产品展示、日常记录、情绪短片等。
- 核心主题：人物、事件、地点、时间或用户想表达的情绪。
- 目标时长：如果用户明确提供，保持原值；没有提供时再使用风格默认值。
- 画幅和平台：只在用户或项目上下文明确时采用；否则选择合理默认值并说明。
- 节奏：慢、平衡、快、卡点，或更具体的节奏变化。
- 视觉方向：构图、镜头距离、运镜、颜色、留白、字幕占比。
- 声音方向：人声、原声、环境声、音乐、配音的优先级。
- 字幕方向：关闭、重点字幕、完整字幕、字幕样式和位置。
- 约束：必须保留、必须删除、不可使用、不能改变的内容。
- 风格候选：一个主风格和零个或多个辅助风格。
- 未解决问题：只有会实质改变成片的问题才列出。

## 风格候选规则

不要把一个词机械映射为一个风格。结合上下文判断用户想要的结果：

- “温柔”通常影响镜头停留、声音密度、转场和字幕克制程度，但不自动等于某一个固定风格。
- “电影感”需要进一步拆成镜头长度、留白、色彩、声音和字幕策略。
- “快一点”优先调整节奏参数，不要无理由改变画幅、字幕和色彩。
- “按照我的风格”必须先读取可用的用户偏好和项目规则，再决定是否存在可用的风格资产。
- 多种风格可以组合，但必须说明哪个是主风格、哪些规则来自辅助风格，以及冲突如何解决。

## 何时询问用户

只有在缺少的信息会改变主要创作方案时询问。例如：

- 用户要求配音，但没有提供文本、语言或音色方向。
- 用户指定“这首歌”，但当前工程中有多首无法区分的候选音乐。
- 用户要求找某个人物，但当前项目没有足够的人物证据。
- 用户没有提供时长，素材数量和目标平台又使默认时长差异很大。

如果缺失信息只影响细节，使用风格默认值并继续。不要让用户重复已经明确说过的要求。

## 内部简报格式

在规划时维护类似下面的结构。它可以在最终回复中压缩成用户能看懂的方案，不需要把原始 JSON 展示给用户。

```text
目标：
视频类型：
主题：
时长：
画幅：
主风格：
辅助风格：
节奏：
画面：
声音：
字幕：
必须保留：
必须避免：
仍需确认：
```
