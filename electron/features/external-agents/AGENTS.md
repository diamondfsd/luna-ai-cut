# 外部 Agent、任务交接和历史规范

先读 [目录索引](README.md)。

- 应用适配器只负责安装探测、打开/下载、草稿或剪贴板交接。不能创建导演计划、操作时间线或保存任务历史。
- 每个应用独立声明能力，不能假定都可下载、安装技能或自动发送。协议探测保持被动，只有用户发起时才打开应用。
- 渲染层不能指定可执行路径、启动命令或下载地址；具体启动方式属于受控适配器。
- 任务创建统一经过 `agentTaskCoordinator.ts`：校验需求与活动任务、创建会话、生成业务指引、保存首次原文及实际提示词，然后交接。禁止先启动外部应用后补存档。
- 原始消息不得因 trim、事件裁剪或后续请求更新而丢失；交接失败记录错误并取消新会话，不能替换其他活动任务。
- `agentConversationStore.ts` 保持串行、原子写入。旧事件不能覆盖新状态；损坏文件不能当空历史重写。历史只包含 Luna 任务消息/事件，不采集外部全部聊天或推理。
- 草稿交接成功不代表任务已发送或完成，完成状态由 Luna 收到的任务报告确认。重启后的历史不自动恢复为活动会话。
- 全局新任务默认 auto，通用提示词只提供服务/工具发现，由技能工具返回技能描述、全文和流程规则；协调器不分类用户需求，旧显式任务类型入口仅兼容调用。执行流程由 agent-workflows 模块交给 Agent 选择，不在适配器中添加业务判断。不通过安装固定 Skill 替代服务最新指引。

适配器回归：`scripts/test-external-agent-adapters.mjs`。
历史/交接回归：`scripts/test-agent-conversations.mjs`。运行范围遵守根目录规则。
